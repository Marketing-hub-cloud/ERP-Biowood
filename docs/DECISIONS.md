# Decisions

บันทึกการตัดสินใจเมื่อสเปกไม่ชัด (CLAUDE.md: "เลือกแบบที่เรียบง่ายที่สุด แล้วจดไว้")

## เฟส 1: Foundation (24/11/2026)

### ฐานข้อมูล: Supabase
- เครื่อง dev ไม่มี Docker / Postgres ผู้ใช้เลือก Supabase
- `DATABASE_URL` = transaction pooler (6543) ใช้ตอนแอปรัน ผ่าน `@prisma/adapter-pg`
- `DIRECT_URL` = session pooler/direct (5432) ใช้ตอน `prisma migrate`
- docker-compose ยังมี service `postgres` (profile `localdb`) ไว้ใช้ภายหลัง

### เวอร์ชัน
- Next.js 16 (middleware เปลี่ยนชื่อเป็น `src/proxy.ts`), Prisma 7 (driver adapter + `prisma.config.ts`),
  Auth.js = `next-auth@5` (beta เพราะยังไม่มี v5 stable), Zod 4, TanStack Table v8 (v9 API ใหม่ ยังไม่ใช้)

### Session / Auth
- ใช้ JWT session (Credentials provider ใช้ database session ไม่ได้)
- **ตรวจสถานะผู้ใช้จาก DB ทุก request** (`getCurrentUser()`) ผู้ใช้ที่ถูกหยุดใช้งานจะหลุดทันที ไม่ต้องรอ token หมดอายุ
- session อายุ 12 ชั่วโมง
- บอกว่า "บัญชีถูกหยุดใช้งาน" เฉพาะเมื่อกรอกรหัสผ่านถูกเท่านั้น (ไม่เปิดเผยว่าอีเมลมีในระบบ)

### ผู้ใช้
- แผนก/ตำแหน่ง เป็นข้อความอิสระ (ยังไม่ทำ master data)
- รหัสผ่านอย่างน้อย 8 ตัวอักษร
- ผู้ใช้เปลี่ยนรหัสผ่านตัวเองต้องกรอกรหัสผ่านปัจจุบัน; เปลี่ยนอีเมลตัวเองไม่ได้ (ให้ admin เปลี่ยน)
- กันพลาด: หยุดใช้งานตัวเองไม่ได้ / ต้องมี admin ที่ใช้งานอยู่อย่างน้อย 1 คน /
  บัญชี admin แก้ไขหรือเปลี่ยนสถานะได้เฉพาะ admin / เฉพาะ admin กำหนด flag admin ได้

### สิทธิ์ (RBAC)
- รายการเมนู (menuKey) อยู่ในโค้ด `src/lib/menu.ts` ไม่ได้เก็บใน DB เพราะเมนูผูกกับหน้าจอที่ต้องเขียนโค้ดอยู่แล้ว
- แต่ละเมนูกำหนดว่ารองรับสิทธิ์ไหนบ้าง เช่น รายงานมีแค่ "ดู", ตั้งค่ามี "ดู/แก้ไข"
- "หยุดใช้งาน/เปิดใช้งาน" ผู้ใช้ ใช้สิทธิ์ `cancel` ของเมนูบัญชีผู้ใช้ (ไม่มีการลบผู้ใช้ จึงไม่มีสิทธิ์ `delete`)
- "แก้ไขข้อมูลส่วนตัว" เป็นเมนู public ทุกคนเห็น
- ไม่มีสิทธิ์ใน page → redirect ไป `/forbidden` (403); ใน API → JSON 403
- "ผู้ติดต่อ > ทั้งหมด": จะแสดงเมื่อมีสิทธิ์ view ลูกค้าหรือผู้ขายอย่างใดอย่างหนึ่ง (ทำในเฟส 2)

### เลขที่เอกสาร
- ตาราง `document_counters (prefix, dateKey)` + `INSERT ... ON CONFLICT DO UPDATE ... RETURNING` (atomic, row lock)
- วันที่ (YYMMDD) คิดตามเวลา Asia/Bangkok
- **ฟอร์มแสดงเลขถัดไปเป็นตัวอย่าง (ไม่จองเลข) ปุ่มรีเฟรช = ขอเลขถัดไปล่าสุด เลขจริงออกตอนบันทึก**
  ถ้ามีคนบันทึกตัดหน้า จะได้เลขถัดไปและแจ้งผู้ใช้ ข้อดีคือเลขไม่ข้าม (transaction ที่ rollback ไม่กินเลข)
- เกิน 9999 ใบ/วัน/ประเภท → error

### Audit log
- เก็บ before/after/changes (เฉพาะฟิลด์ที่เปลี่ยน) ใน transaction เดียวกับการบันทึก
- ไม่เก็บ passwordHash; การเปลี่ยนรหัสผ่านบันทึกเป็นหมายเหตุ "เปลี่ยนรหัสผ่าน"
- กลุ่มสิทธิ์เก็บ snapshot เป็นข้อความอ่านง่าย เช่น `purchase.request: view,create`
- ไม่ log การล็อกอิน (เก็บแค่ `lastLoginAt`)

### หน้ารายการ (DataTable)
- ทำ component กลางตั้งแต่เฟส 1 (เดิมอยู่เฟส 2) เพราะหน้าผู้ใช้/กลุ่มสิทธิ์ต้องใช้
- pagination/ค้นหา/กรอง/เรียง ทำฝั่ง server; Export CSV ส่งออกทุกแถวตามตัวกรองปัจจุบัน (ไม่ใช่แค่หน้าที่เห็น)
- Density และ Columns จำค่าไว้ใน localStorage ของเบราว์เซอร์
- CSV: UTF-8 BOM + CRLF และกัน CSV injection (ขึ้นต้นด้วย `= + - @` จะเติม `'` นำหน้า ยกเว้นตัวเลข)

### ไฟล์
- dev เก็บที่ `./uploads` ผ่าน interface `Storage` (`src/lib/storage.ts`) เปลี่ยนเป็น S3 ได้ภายหลัง
- ไฟล์ทุกไฟล์เปิดผ่าน `/api/files/...` และต้องล็อกอินก่อน
- โลโก้: PNG/JPG/WEBP/GIF ไม่เกิน 5MB

### การแจ้งเตือน
- เฟส 1 มีแค่ไอคอนกระดิ่ง (badge = 0) ระบบจริงทำในเฟส 6

### Next.js config
- ปิด `cacheComponents` / `partialPrefetching` ที่ create-next-app เปิดไว้ เพราะทุกหน้าต้องล็อกอินและขึ้นกับสิทธิ์ผู้ใช้ (dynamic ทั้งหมด) ทำให้โค้ดเรียบง่ายกว่า

## เฟส 2: ผู้ติดต่อ (24/11/2026)

ผู้ใช้เลือก "ตามแนะนำ" ทั้ง 3 ข้อ:
- รหัสผู้ติดต่อแบบเดียว `CT00001` ทุกบทบาท (เว้นว่าง = สร้างอัตโนมัติ, แก้ได้, ห้ามซ้ำ, ข้ามเลขที่ถูกตั้งเองไปแล้ว)
  ใช้ตาราง `document_counters` (prefix `CT`, dateKey ว่าง) ไม่รีเซ็ตรายวัน
- เลขผู้เสียภาษี ตรวจแค่ตัวเลข 13 หลัก (ไม่ตรวจ checksum) — ตัดขีด/ช่องว่างให้อัตโนมัติ
- ที่อยู่กรอกเอง จังหวัดมีรายการ 77 จังหวัดให้เลือก (datalist พิมพ์อย่างอื่นได้ เช่น ที่อยู่ต่างประเทศ)

อื่นๆ:
- สิทธิ์ตามบทบาท: ดู/แก้ไข = มีสิทธิ์บทบาทใดบทบาทหนึ่ง; **ลบ = ต้องมีสิทธิ์ลบทุกบทบาท**;
  เพิ่ม/เอาออกบทบาท = ต้องมีสิทธิ์ของบทบาทนั้น (create ตอนสร้าง, edit ตอนแก้ไข)
- แท็บ: `/contacts/all`, `/contacts/customers`, `/contacts/vendors` (แท็บที่ไม่มีสิทธิ์จะไม่แสดง)
- ลบแบบ soft delete (`deletedAt`); รหัสของรายการที่ลบแล้วยังใช้ซ้ำไม่ได้
- ตัวเลือก "ช่องทางที่รู้จัก" / "ประเภทกิจการของลูกค้า" อยู่ในตาราง `lookup_options` เพิ่มจากในฟอร์มได้ (ปุ่ม +)
  ผู้ที่สร้าง/แก้ไขผู้ติดต่อได้ (บทบาทใดก็ได้) เพิ่มตัวเลือกและ tag ได้; ยังไม่มีหน้าจัดการ/ลบตัวเลือก
- tag ใช้ตาราง `tags` กลาง (เตรียมใช้กับโครงการ CRM)
- ที่อยู่จัดส่ง/บุคคลติดต่อ มี "หลัก" ได้รายการเดียว (ถ้าไม่ติ๊กเลย รายการแรกเป็นหลัก)
- บันทึกผู้ติดต่อ = แทนที่รายการย่อยทั้งหมด (ที่อยู่/ช่องทาง/บุคคล/tag) ใน transaction เดียว; audit เก็บเป็นข้อความอ่านง่าย
- รูปผู้ติดต่อ: ตอนสร้างใหม่จะอัปโหลดหลังบันทึกสำเร็จ; ตอนแก้ไขอัปโหลดทันที
- คอลัมน์ "จำนวนโครงการ" แสดง 0 จนกว่าจะมีโมดูลโครงการ (เฟส 8)
- Export CSV ส่งออกตามแท็บ + ตัวกรองปัจจุบัน แยกคอลัมน์ โทรศัพท์/อีเมล/LINE
- `npm run db:migrate` รัน `prisma generate` ต่อท้ายด้วย (Prisma 7 ไม่ generate ให้อัตโนมัติ) และต้องรีสตาร์ท dev server หลังเปลี่ยน schema

## เฟส 3: ตั้งค่าคลัง + สินค้า (24/11/2026)

ผู้ใช้เลือก "ตามแนะนำ" ทั้ง 3 ข้อ:
- รหัสสินค้า: กรอกเอง บังคับ ห้ามซ้ำ (แปลงเป็นตัวพิมพ์ใหญ่, ใช้ได้ A-Z 0-9 - _ . /) — รหัสของสินค้าที่ลบแล้วใช้ซ้ำไม่ได้
- 1 สินค้า = 1 หน่วยสต๊อก (ไม่มีการแปลงหน่วย)
- รูปสินค้าได้หลายรูป (สูงสุด 10) รูปแรกเป็นรูปหลัก

อื่นๆ:
- สถานที่จัดเก็บ: ตาราง `stock_locations` เดียว คลัง = level 0, ซ้อนได้ถึง level 3; รหัสบังคับ ห้ามซ้ำในระดับเดียวกัน (ภายใต้ parent เดียวกัน)
- หมวดหมู่: level 1–3; รหัสไม่บังคับ; ชื่อห้ามซ้ำภายใต้ parent เดียวกัน; สินค้าเก็บ `categoryId` เป็นหมวดระดับลึกสุดที่เลือก (หมวด 1/2/3 คำนวณจาก parent)
- ย้ายโหนดได้ (เลือก "อยู่ภายใต้") ลูกหลานย้ายตามและปรับระดับให้; ห้ามย้ายไปใต้ตัวเอง/ลูกหลาน และห้ามลึกเกินเมื่อรวม subtree
- ลบได้เฉพาะรายการที่ไม่มีรายการย่อยและไม่มีการใช้งาน (หมวด/หน่วย/คุณสมบัติที่สินค้าใช้อยู่) — ถ้าใช้อยู่ให้ "ปิดใช้งาน";
  รายการที่ปิดใช้งานเลือกใหม่ไม่ได้ แต่สินค้าที่ใช้อยู่แล้วยังแสดง/บันทึกค่าเดิมได้
- คุณสมบัติ: ค่าเก็บเป็นข้อความ ตรวจชนิดที่ server; ตัวเลขตัด comma ออก; เปลี่ยนชนิดข้อมูลไม่ได้ถ้ามีสินค้าใช้, ลบตัวเลือกที่สินค้าใช้อยู่ไม่ได้;
  คุณสมบัติที่ปิดใช้งานไม่บังคับกรอกและค่าเดิมของสินค้ายังเก็บไว้
- ประเภทสินค้าใช้ `lookup_options` (kind `PRODUCT_TYPE`) เพิ่มได้จากฟอร์มสินค้า (ผู้มีสิทธิ์สร้าง/แก้ไขสินค้า)
- หน้าตั้งค่าคลังใช้สิทธิ์ `settings.inventory` (ดู/แก้ไข) ทั้ง 4 แท็บ
- สินค้า: ลบแบบ soft delete; "ปิดใช้งาน" แก้ได้ในฟอร์ม (สิทธิ์แก้ไข)
- คงเหลือ / แท็บจำนวนสินค้าคงคลัง: คำนวณจาก stock ledger (ทำแล้วในเฟส 4)

### e2e ล้างข้อมูลทดสอบอัตโนมัติ
- ข้อมูลที่ e2e สร้างต้องมี marker `e2e` ในชื่อ/รหัส (`uid()` ใส่ให้) ผู้ใช้ทดสอบใช้อีเมล `@test.local`, กลุ่ม `E2E-…`
- `tests/e2e/cleanup.ts` ลบข้อมูลเหล่านี้ (+ audit log + ไฟล์รูป) ทั้งก่อนเริ่ม (ของค้าง) และหลังจบ
  และคืนค่าข้อมูลบริษัทจาก snapshot; ตั้ง `E2E_KEEP_DATA=1` เพื่อเก็บไว้ดู
- e2e ไม่พึ่งข้อมูลตัวอย่างจาก seed (ผู้ใช้ลบข้อมูลตัวอย่างได้)
- Prisma `migrate dev` อาจถาม prompt (เช่น เพิ่มค่า enum) ในโหมด non-interactive จะค้าง → ใช้ `npm run db:migrate:create` แล้ว `npx prisma migrate deploy` + `prisma generate`

## เฟส 4: นำเข้า / นำออก / Stock ledger / Barcode + label / สแกน (24/11/2026)

ผู้ใช้เลือก "ตามแนะนำ" ทุกข้อ:
- **จำนวนเป็นทศนิยมได้ 3 ตำแหน่ง** (`Decimal(14,3)`) ฝั่ง JS คำนวณเป็นหน่วย 1/1000 (`lib/stock-rules.ts`) กันเศษ float
- **สถานที่จัดเก็บเลือกต่อรายการ** มีปุ่ม "ใช้กับทุกรายการ"; เลือกตัวคลัง (ระดับ 0) เป็นสถานที่ได้
- **Barcode = เลขที่ GR + "-" + ลำดับ 3 หลัก** เช่น `GR2611240001-001` (ไม่เกิน 999 SN ต่อใบ, สร้างครั้งละไม่เกิน 500)
- **ขนาด label จำไว้ในเครื่อง** (localStorage) มี 50×30 / 40×25 / 60×40 / 100×50 / กำหนดเอง
- **ยกเลิกใบที่นำเข้า/นำออกแล้วได้** โดยเขียน movement กลับรายการ (ไม่ลบของเดิม) ต้องกรอกเหตุผล (สิทธิ์ `cancel`)

### Stock ledger
- `stock_movements` เพิ่มอย่างเดียว: DB trigger ห้าม UPDATE; CHECK `quantity <> 0`
- ยอดคงเหลือ = `SUM(quantity)` เท่านั้น ไม่มีคอลัมน์ยอดคงเหลือเก็บไว้ที่ไหน
- กันยอดติดลบเมื่อกดพร้อมกัน: ใน transaction เดียวกัน lock แถวเอกสาร + แถว SN (`SELECT … FOR UPDATE` เรียงตาม id) แล้วจึงคำนวณยอด
  (เทสใน `tests/db/stock-ledger.test.ts` และ e2e ยิง API พร้อมกัน 2 ครั้ง)
- transaction ของเอกสารคลังใช้ timeout 30 วินาที / รอ connection 10 วินาที (`STOCK_TX`) เพราะ DB อยู่ภายนอก (Supabase)
  ถ้าใช้ค่าเริ่มต้น 5 วินาที request ที่รอ lock จะ timeout เป็น error 500 แทนที่จะได้ข้อความ "เกินคงเหลือ"
- ไม่คิดต้นทุนสต๊อก (หัวข้อ 10 ยังไม่มีสเปก) เก็บแค่จำนวน
- movement ใช้เวลาที่กด "นำเข้า/นำออก" (`occurredAt`) ส่วน "วันที่เอกสาร" เป็นข้อมูลแสดงผล
- เลขที่เอกสารออกตอนบันทึกครั้งแรก (วันที่ในเลขคือวันที่สร้าง ไม่ใช่วันที่เอกสาร)

### ใบนำเข้า (GR)
- ขั้นตอน: บันทึกร่าง (ได้เลข) → สร้าง SN ต่อรายการ → พิมพ์ label → สแกน → "นำเข้า" (กดได้เมื่อทุกรายการมี SN, สแกนครบ, เลือกสถานที่ครบ)
- จำนวนของรายการ = ผลรวมจำนวนของ SN (ไม่มีช่องกรอกจำนวนแยก)
- สถานะการสแกนเก็บใน DB ทันที (ปิดหน้าแล้วสแกนต่อได้) ยกเลิกสแกนรายตัวได้ระหว่างเป็นร่าง
- ต้องบันทึกการแก้ไขก่อนสร้าง SN / สแกน / นำเข้า; เปลี่ยนสินค้าของรายการที่มี SN แล้วไม่ได้
- คลัง/สถานที่/Lot คัดลอกไปที่ SN ตอนกด "นำเข้า"
- ยกเลิก GR ที่นำเข้าแล้ว ได้เฉพาะเมื่อทุก SN ยังเหลือเต็มจำนวน (ต้องยกเลิกใบนำออกที่เกี่ยวข้องก่อน)
- ประเภท "สั่งซื้อ" แสดงแต่เลือกไม่ได้จนถึงเฟส 5 (จัดซื้อ)

### ใบนำออก (GI)
- ประเภท ขาย (ต้องเลือกผู้ติดต่อที่เป็นลูกค้า) / เบิกตัวอย่าง / อื่นๆ; "ส่งคืน" เลือกไม่ได้จนถึงเฟส 5
- สแกน SN แล้วเพิ่มรายการพร้อมคงเหลือ (ค่าเริ่มต้นจำนวน = คงเหลือทั้งหมด) แก้จำนวนได้ ห้ามเกินคงเหลือ
- ที่อยู่จัดส่ง: เลือกจากที่อยู่จัดส่ง/จดทะเบียนของผู้ติดต่อ แล้วคัดลอกเป็นข้อความที่แก้ได้ (ไม่ผูกกับที่อยู่ต้นทาง)
- ผู้ที่สร้าง/แก้ใบนำออกได้ ค้นหาผู้ติดต่อได้ผ่าน `/api/inventory/issues/contacts` แม้ไม่มีสิทธิ์เมนูผู้ติดต่อ (เห็นแค่รหัส ชื่อ ที่อยู่)
- ปุ่ม "นำออก" ในฟอร์มใหม่ = สร้าง + นำออกใน transaction เดียว (ไม่สำเร็จ = ไม่บันทึกอะไร)

### สิทธิ์

## เฟส 5: จัดซื้อ + Approval engine + พิมพ์เอกสาร + หมายเหตุสำเร็จรูป (24/11/2026)

ผู้ใช้เลือก "ตามแนะนำ" ทุกข้อ (รวมสูตรราคาในหัวข้อ 10):

### สูตรราคาใบสั่งซื้อ (`src/lib/purchase-calc.ts`)
- ยอดต่อรายการ = ปัด 2 ตำแหน่ง(จำนวน × ราคาต่อหน่วย) − ส่วนลดของรายการ (บาท)
- รวมเป็นเงิน = ผลรวมรายการ − ส่วนลดท้ายบิล (บาท)
- VAT 7% เลือกต่อใบ: แยกนอก (ค่าเริ่มต้น, VAT = รวม × 7%) / รวมใน (VAT = รวม × 7/107) / ไม่มี VAT
- ปัดเศษ 2 ตำแหน่งแบบครึ่งขึ้นทุกจุด, ไม่มีหัก ณ ที่จ่าย; คำนวณด้วย BigInt (ไม่ใช้ float)
- ราคาต่อหน่วยเก็บทศนิยม 4 ตำแหน่ง, เงินเก็บ 2 ตำแหน่ง; server คำนวณยอดใหม่ทุกครั้งที่บันทึก (ไม่เชื่อค่าจาก client)

### Approval engine (`src/lib/approval.ts`, `src/server/approval.ts`)
- **ผังอนุมัติแยกตามชนิดเอกสาร** (PR / PO / ใบส่งคืน) ที่ "ตั้งค่า > การอนุมัติ > จัดซื้อ" สูงสุด 3 ลำดับ
- ลำดับเดียวกันมีผู้อนุมัติหลายคน คนใดคนหนึ่งกดก็ไปลำดับถัดไป; ไม่อนุมัติต้องมีเหตุผล แล้วกลับเป็นร่าง
- ส่งใหม่ = รอบใหม่ (approvalRound) เริ่มลำดับ 1; ประวัติเก็บใน `approval_actions` (ใคร เมื่อไร ความเห็น รอบ ลำดับ)
- ผังถูกคัดลอกลงเอกสารตอนกด "ส่ง" (`approvalSnapshot`) แก้ตั้งค่าภายหลังไม่กระทบใบที่รออยู่
- **เพิ่มสิทธิ์ใหม่ "อนุมัติ" (approve)** ในหน้ากำหนดสิทธิ์ เฉพาะเมนู PR/PO/ใบส่งคืน — ใช้เมื่อ *ไม่ได้ตั้งผัง*
  ถ้าตั้งผังแล้ว อนุมัติได้เฉพาะคนในลำดับปัจจุบัน (admin ที่ไม่อยู่ในผังก็กดไม่ได้)
- ส่งอนุมัติ = สิทธิ์แก้ไข; แก้เอกสารได้เฉพาะร่าง; ยกเลิก = สิทธิ์ยกเลิก (ต้องมีเหตุผล)
- กลุ่มสิทธิ์ "จัดซื้อ" ที่ seed ไว้ก่อนเฟสนี้ ไม่ได้ถูกเพิ่มสิทธิ์อนุมัติให้อัตโนมัติ (แก้ได้ที่หน้ากำหนดสิทธิ์)

### สถานะและจำนวนสะสม (`src/lib/purchase-status.ts`)
- สถานะ: ร่าง → รออนุมัติ → อนุมัติแล้ว → บางส่วน → ครบ (+ ยกเลิก) ชื่อบางส่วน/ครบ ต่างกันตามชนิดเอกสาร
- จำนวนสะสมคำนวณจากเอกสารที่อ้างอิง ไม่เก็บเป็นตัวเลข แล้วคำนวณสถานะใหม่ใน transaction เดียวกับเอกสารที่เปลี่ยน
  - **สั่งซื้อแล้ว (PR) นับ PO ทุกใบที่ยังไม่ยกเลิก รวมร่าง** (กันสั่งเกินคงค้าง) — สร้าง PO ร่างแล้ว PR จะเป็น "สั่งซื้อแล้ว(บางส่วน)" ทันที
  - นำเข้าแล้ว (PO) นับเฉพาะใบนำเข้าที่ "นำเข้าแล้ว"; ส่งคืนแล้ว (ใบส่งคืน) นับเฉพาะใบนำออกที่ "นำออกแล้ว"
  - การส่งคืนไม่ลดจำนวน "นำเข้าแล้ว" ของ PO
- กันเกินคงค้างเมื่อกดพร้อมกัน: lock แถว PR/PO/ใบส่งคืน (`FOR UPDATE`) ก่อนคำนวณ (เทสใน `tests/db/purchase.test.ts`)
- ยกเลิกได้เมื่อไม่มีเอกสารปลายทางที่ยังไม่ยกเลิก (PR ← PO, PO ← ใบนำเข้า/ใบส่งคืน, ใบส่งคืน ← ใบนำออก)

### PR / PO / ใบส่งคืน
- PR: ผู้ขอเริ่มต้น = ผู้สร้าง เลือกคนอื่นได้ แผนก/ตำแหน่งดึงจากผู้ขอแล้วแก้ได้; หน่วย = หน่วยสต๊อกของสินค้า
- PO: สร้างจาก PR ("สร้าง > ใบสั่งซื้อ" หรือปุ่ม "เพิ่มจากใบขอซื้อ" เลือกได้หลาย PR) หรือเพิ่มรายการเองที่ไม่มี PR ได้
  รายการที่มาจาก PR เปลี่ยนสินค้าไม่ได้ แก้จำนวนได้ไม่เกินคงค้าง; ผู้ขายต้องเป็นผู้ติดต่อที่ติ๊ก "ผู้ขาย"
- **นำเข้าจาก PO ห้ามเกินจำนวนสั่ง** ตรวจตอนกด "นำเข้า" (lock PO) ใบนำเข้าแบบสั่งซื้อเพิ่มรายการเองไม่ได้ ต้องมาจาก PO
  สินค้าใน PO ที่ไม่ได้ตั้ง "สต๊อกได้" จะไม่ถูกดึงมาในใบนำเข้า
- ใบส่งคืน: สร้างจาก PO ที่มีการนำเข้าแล้ว คืนได้ไม่เกิน นำเข้าแล้ว − ใบส่งคืนอื่นที่ยังไม่ยกเลิก; ผู้ขาย = ผู้ขายของ PO
  เหตุผลการคืนเก็บใน `lookup_options` (kind `RETURN_REASON`) พิมพ์เพิ่มได้จากฟอร์ม
- **นำออกประเภทส่งคืนต้องสแกน SN** สินค้าต้องอยู่ในใบส่งคืน จำนวนเริ่มต้น = ไม่เกินที่ต้องคืน, ผู้รับ = ผู้ขาย (แก้ไม่ได้)
  ระบบจับคู่แต่ละ SN กับรายการในใบส่งคืนให้อัตโนมัติ
- ไม่มีการลบเอกสารจัดซื้อ ใช้ "ยกเลิก" แทน (เลขที่เอกสารไม่หาย)

### พิมพ์เอกสาร / หมายเหตุสำเร็จรูป / อื่นๆ
- หน้าพิมพ์ `/print/purchase/{requests|orders|returns}/[id]` ขนาด A4: โลโก้ (ถ้าไม่ได้อัปโหลดใช้ `public/logo.png`), ข้อมูลบริษัท,
  หัว "ใบขอซื้อ/PurchaseRequest", "ใบสั่งซื้อ/PurchaseOrder", "ใบส่งคืนสินค้า/PurchaseReturn" + "(ต้นฉบับ/Original)"
  ช่องเซ็นชื่อใส่ชื่อผู้อนุมัติลำดับสุดท้ายให้; เอกสารที่ยกเลิกมีลายน้ำ "ยกเลิก"
- หมายเหตุสำเร็จรูป: เลือกแล้ว **ต่อท้าย** ข้อความเดิม (ขึ้นบรรทัดใหม่) แก้ต่อได้; ลบได้เสมอเพราะเอกสารเก็บข้อความที่คัดลอกไปแล้ว
- ค้นหาผู้ติดต่อในเอกสาร (`/api/contact-options`) ใช้ได้ทั้งใบนำออก / PO / ใบส่งคืน แม้ไม่มีสิทธิ์เมนูผู้ติดต่อ
- แจ้งเตือน (ในระบบ + LINE) ยังไม่ส่งจริง มีจุดเรียก `notifyPurchaseEvent` ไว้แล้ว ทำในเฟส 6
- รายงานจัดซื้อทำในเฟส 9 (หน้ารายการ PR/PO/ใบส่งคืน มี Export CSV แบบ 1 แถวต่อรายการแล้ว)
- e2e เก็บ/คืนค่าผังอนุมัติให้อัตโนมัติ (`tests/e2e/cleanup.ts`); Vitest เรียก logic ฝั่ง server ได้ (stub `server-only`)

## เฟส 6: แจ้งเตือน (ในระบบ + LINE Messaging API) (24/11/2026)

ผู้ใช้เลือก "ตามแนะนำ" (ยังไม่มี LINE channel จึงทดสอบด้วย LINE จำลอง — ขั้นตอนตั้งค่าจริงอยู่ใน README)

### ค่าลับ / การตั้งค่า
- **token อยู่ใน `.env` เท่านั้น** (`LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`, `APP_BASE_URL`) หน้า "ตั้งค่า > การแจ้งเตือน"
  แสดงแค่สถานะ ตั้งแล้ว/ยังไม่ตั้ง; ตั้งค่าในหน้าเว็บได้เฉพาะ เปิด/ปิด และกลุ่ม LINE ต่อโมดูล (สิทธิ์ `settings.notification`)
- groupId ได้จาก webhook `/api/line/webhook` (ตรวจลายเซ็น HMAC; ไม่ต้องล็อกอิน) เมื่อบอทเข้ากลุ่มหรือมีข้อความในกลุ่ม หรือกรอกเองได้
- ใช้ push message แบบ text ธรรมดา (ไม่ใช้ Flex) ข้อความ: เหตุการณ์ + ชนิด/เลขที่เอกสาร, สถานะ, ผู้ทำ, เหตุผล/ความเห็น, ลิงก์

### ส่งผ่าน background job + retry (`src/lib/notification-worker.ts`)
- outbox: ข้อความเข้าคิว `notification_deliveries` **ใน transaction เดียวกับเอกสาร** → เอกสารบันทึกไม่สำเร็จ = ไม่มีคิว,
  ส่ง LINE ล้ม = ไม่กระทบเอกสาร
- worker รันในแอป (เริ่มจาก `src/instrumentation.ts`) ทุก 15 วินาที + ปลุกทันทีหลังบันทึกเอกสาร
  จองคิวด้วย `FOR UPDATE SKIP LOCKED` (หลาย worker ไม่ส่งซ้ำ) และส่ง `X-Line-Retry-Key` (UUID คงที่ต่อคิว) กัน LINE ส่งซ้ำหลัง timeout
- ล้มชั่วคราว (429 / 5xx / network / timeout 10 วิ): ลองใหม่ 1 นาที → 5 นาที → 15 นาที → 1 ชม. → 6 ชม. ครบ 6 ครั้ง = ส่งไม่สำเร็จ
- ผิดถาวร (4xx อื่น เช่น token/groupId ผิด, บอทไม่อยู่ในกลุ่ม) = ส่งไม่สำเร็จทันที; กด "ส่งซ้ำ" ในหน้าตั้งค่าได้ (เริ่มนับใหม่)
- ยังไม่ตั้ง token: worker ไม่แตะคิว ข้อความรอจนกว่าจะตั้งค่า; ปิด LINE ของโมดูล: ไม่เข้าคิวเลย (แจ้งเตือนในระบบยังมี)
- คิวที่ค้าง "กำลังส่ง" เกิน 5 นาที (worker ตายกลางทาง) ถูกหยิบส่งใหม่
- ทางเลือกสำหรับ deploy ที่รัน background ไม่ได้: `NOTIFY_WORKER=off` + cron เรียก `POST /api/jobs/notifications` (Bearer `CRON_SECRET`)

### แจ้งเตือนในระบบ (กระดิ่ง)
- ผู้รับ (จัดซื้อ):
  - ส่งอนุมัติ / ผ่านไปลำดับถัดไป → ผู้อนุมัติของลำดับนั้น (ไม่ได้ตั้งผัง = ผู้มีสิทธิ์ "อนุมัติ" ของเมนู + admin)
  - อนุมัติครบ / ไม่อนุมัติ / ยกเลิก / สถานะต่อเนื่อง (สั่งซื้อแล้ว, นำเข้าแล้ว, ส่งคืนแล้ว) → ผู้สร้าง (+ ผู้ขอของ PR)
  - ไม่แจ้งผู้ที่กดเอง และผู้ใช้ที่ถูกหยุดใช้งาน; "สร้างเอกสาร" ส่งเฉพาะ LINE
- LINE ส่งทุกเหตุการณ์: สร้าง, ส่งอนุมัติ, อนุมัติแต่ละลำดับ, ไม่อนุมัติ, ยกเลิก, สถานะต่อเนื่อง
- กระดิ่งถามเซิร์ฟเวอร์ทุก 30 วินาที (เฉพาะตอนแท็บแสดงอยู่) และทุกครั้งที่เปลี่ยนหน้า; กดรายการ = อ่านแล้ว + เปิดเอกสาร
- หน้า `/notifications` แสดงทั้งหมด (โหลดเพิ่มทีละ 30) กรองยังไม่อ่าน, อ่านทั้งหมด
- แจ้งเตือนของเอกสารคลัง (นำเข้า/นำออก) ไม่มีในสเปก จึงยังไม่ทำ; โมดูลถอดแบบ/ติดตั้งตั้งกลุ่มได้แล้ว เริ่มส่งในเฟส 7

### อื่นๆ
- Vitest รันทีละไฟล์ (`fileParallelism: false`) เพราะเทส DB หลายไฟล์แก้ค่ากลางเดียวกัน (ผังอนุมัติ, ตั้งค่าแจ้งเตือน)
- e2e เก็บ/คืนค่าตั้งค่าแจ้งเตือนอัตโนมัติเหมือนผังอนุมัติ
- หลัง `prisma generate` ถ้า dev server ยังใช้ client เก่า (error `reading 'count'` ของ model ใหม่) ให้ลบ `.next` แล้วรันใหม่
- **Prisma `relationJoins`** (previewFeatures): โหลด `include` ซ้อนหลายชั้นเป็น SQL เดียว (JOIN) แทนการยิงทีละชั้น
  วัดกับ Supabase แล้ว include ของใบนำเข้าเร็วขึ้นจาก ~546ms เหลือ ~105ms (≈ 1 round trip) — จำเป็นหลังเฟส 6
  เพราะการแจ้งเตือนเพิ่ม query ในทุก transaction ของเอกสาร (เดิม e2e บางขั้นใช้เวลาเกิน 10 วินาที)
- เทสที่แก้ผังอนุมัติ/ตั้งค่าแจ้งเตือน ต้องคืนค่าเองเมื่อจบเทส (ไม่รอ teardown) เพราะเทสอื่นในรอบเดียวกันคาดว่าไม่มีผัง

## เฟส 7: ถอดแบบ/ติดตั้ง (25/11/2026)

### State machine (`src/lib/engineer-workflow.ts`)
- 9 ขั้นตามคู่มือ: ร่าง → งานถอดแบบใหม่ → ตรวจสอบแล้ว → รับลงคิว → มอบหมาย → ดำเนินงาน → ตรวจรับงาน → ใบสรุปประมาณถอดแบบ → เสร็จสิ้น (+ ยกเลิก)
- ตาราง `TRANSITIONS` กำหนดต่อขั้น: ปุ่ม, **สิทธิ์ที่ต้องใช้**, ผู้รับผิดชอบกดได้หรือไม่, เงื่อนไขก่อนไปต่อ — แก้ที่ไฟล์นี้ที่เดียว UI และ server ใช้ร่วมกัน
  - "ดำเนินการต่อ" / "บันทึกเสร็จสิ้น" = สิทธิ์ **แก้ไข**; "อนุมัติ" = สิทธิ์ **อนุมัติ** (เพิ่มสิทธิ์ "อนุมัติ" ให้เมนูใบถอดแบบ/ติดตั้ง)
  - **ผู้รับผิดชอบงาน** กด มอบหมาย→ดำเนินงาน และ ดำเนินงาน→ตรวจรับงาน ได้เอง แม้มีแค่สิทธิ์ดู (ช่างไม่ต้องได้สิทธิ์แก้ไขทั้งเอกสาร)
  - เงื่อนไข: ออกจากร่างต้องมีลูกค้า; อนุมัติมอบหมายต้องเลือกผู้รับผิดชอบ; ส่งตรวจรับงานต้องแนบ "เอกสารส่งกลับ" ≥ 1 ไฟล์;
    เสร็จสิ้นต้องมีรายการในใบสรุปประมาณ ≥ 1 รายการ **เฉพาะเมื่อประเภทงานมี "ถอดแบบ"** (งานติดตั้งอย่างเดียวไม่บังคับ)
- ไม่ได้ใช้ approval engine ของจัดซื้อ (ผังลำดับผู้อนุมัติ) เพราะคู่มือไม่ได้ระบุ — ขั้นอนุมัติใช้สิทธิ์ "อนุมัติ" ของเมนูตรงๆ
- ไม่มีปุ่ม "ไม่อนุมัติ/ส่งกลับขั้นก่อน" (คู่มือไม่ได้ระบุ) — ถ้าต้องการ เพิ่ม transition ย้อนกลับในตารางได้
- ส่ง `from` (ขั้นที่ผู้ใช้เห็น) มากับทุกการกด + lock แถว `FOR UPDATE` → กดซ้ำ/กดพร้อมกันสำเร็จครั้งเดียว อีกครั้งได้ 409
- ทุกการเปลี่ยนขั้นเก็บใน `engineer_step_logs` (จาก → ถึง, ใคร, เมื่อไร, ความเห็น) แสดงเป็น "ประวัติขั้นตอน" ข้างเอกสาร
  และเก็บ audit log ด้วย (อนุมัติ = APPROVE, อื่นๆ = STATUS_CHANGE) เปิดดูจากไอคอนนาฬิกา
- ยกเลิกได้ทุกขั้นที่ยังไม่เสร็จสิ้น (สิทธิ์ยกเลิก + เหตุผล); stepper ของใบที่ยกเลิกแสดงขั้นที่ไปถึงก่อนยกเลิก

### ข้อมูลเอกสาร
- แก้ไขข้อมูลได้ทุกขั้นที่ยังไม่เสร็จสิ้น/ยกเลิก (สิทธิ์แก้ไข); กด "ดำเนินการต่อ/อนุมัติ" ตอนมีการแก้ไขค้าง ระบบบันทึกให้ก่อน
- ลูกค้า: ดินสอ > เลือกลูกค้า (เฉพาะผู้ติดต่อที่เป็นลูกค้า) > เลือกที่อยู่จัดส่ง/จดทะเบียน > เพิ่ม → **คัดลอกข้อความที่อยู่** ลงช่อง "ที่อยู่หน้างาน" (แก้ต่อได้ ไม่เปลี่ยนตามผู้ติดต่อภายหลัง)
- ผู้เกี่ยวข้อง (หลายคน แสดงเป็น avatar) ค่าเริ่มต้น = ผู้สร้าง; ผู้รับผิดชอบงานเลือกได้ทุกขั้น แต่หลังมอบหมายแล้วเอาออกไม่ได้
- ชื่อโครงการเป็นข้อความ — การเชื่อมกับโครงการ CRM (FK + ปุ่ม "สร้างใบถอดแบบ" จากหน้าโครงการ) ทำในเฟส 8
- ใบสรุปประมาณถอดแบบ (สินค้า, จำนวน, หน่วย = หน่วยสต๊อก, หมายเหตุ) แสดงตั้งแต่ขั้นดำเนินงาน ไม่ตัดสต๊อก
- ยังไม่มีหน้าพิมพ์ใบถอดแบบ (สเปกไม่ได้ระบุ)

### ไฟล์แนบ
- 2 ประเภท: "แบบจากลูกค้า" (แนบได้ทุกขั้นที่ยังไม่จบ, สิทธิ์แก้ไข) และ "เอกสารส่งกลับ" (ตั้งแต่ขั้นมอบหมาย, สิทธิ์แก้ไขหรือผู้รับผิดชอบงาน)
- ชนิดที่รับ: PDF, รูป (PNG/JPG/WEBP/GIF), DWG, DXF, SKP, Excel, Word, PowerPoint, CSV, TXT, ZIP/RAR/7Z ไม่เกิน 25MB ต่อไฟล์, 50 ไฟล์ต่อเอกสาร
  (ไม่รับ HTML/SVG/โปรแกรม) — ตั้ง `experimental.proxyClientMaxBodySize = 30mb` เพราะ proxy buffer body ได้แค่ 10MB โดยปริยาย
- เปิด/ดาวน์โหลดผ่าน `/api/engineer/documents/[id]/files/[fileId]` ที่ตรวจสิทธิ์ดูเมนู (ชื่อไฟล์ภาษาไทยถูกต้อง), รูป/PDF เปิดในเบราว์เซอร์ อย่างอื่นดาวน์โหลด
  `/api/files/engineer/...` ถูกปิด (เดิมแค่ล็อกอินก็เปิดได้)
- สร้างใบใหม่ต้อง "บันทึกร่าง" ก่อนจึงแนบไฟล์ได้

### แจ้งเตือน
- LINE "Biowood - ถอดแบบติดตั้ง": สร้างเอกสาร, ทุกครั้งที่เปลี่ยนขั้น (ขั้นเดิม → ขั้นใหม่), ยกเลิก — ใช้ outbox/worker เดิมของเฟส 6
- ในระบบ: ผู้สร้าง + ผู้เกี่ยวข้อง + ผู้รับผิดชอบ ทุกครั้งที่เปลี่ยนขั้น/ยกเลิก; ผู้รับผิดชอบได้ "คุณได้รับมอบหมายงาน" ตอนถึงขั้นมอบหมาย;
  ถึงขั้นที่ต้องอนุมัติ (งานถอดแบบใหม่, รับลงคิว, ตรวจรับงาน) แจ้งผู้มีสิทธิ์ "อนุมัติ" (+ admin); ไม่แจ้งผู้กดเอง
- seed กลุ่มสิทธิ์ใหม่ "ถอดแบบ/ติดตั้ง" (ใบถอดแบบทุกสิทธิ์รวมอนุมัติ, ดูลูกค้า/สินค้า)

## เฟส 8: CRM — โครงการ, แผนการทำงาน + GPS check-in (25/11/2026)

### โครงการ
- สถานะ 9 ขั้น (stepper แนวนอน) เปลี่ยนผ่าน dropdown "สถานะ" แล้วกดบันทึก; เปลี่ยนไปขั้นไหนก็ได้ (ไม่บังคับเรียงลำดับ — คู่มือไม่ได้ระบุ)
- "การเคลื่อนไหว" = audit log ของโครงการ (แท็บในหน้าโครงการ + ไอคอนนาฬิกา) การเปลี่ยนสถานะเก็บเป็น STATUS_CHANGE พร้อมข้อความ "เปลี่ยนสถานะ: เดิม → ใหม่"
- **บุคคลติดต่อเก็บเป็นข้อความ** (เลือกจากบุคคลติดต่อของลูกค้าแล้วคัดลอก ชื่อ/ตำแหน่ง/เบอร์ หรือพิมพ์เอง) เพราะบุคคลติดต่อถูกสร้างใหม่ทุกครั้งที่แก้ผู้ติดต่อ (FK จะหลุด)
- ลูกค้าต้องเป็นผู้ติดต่อที่ติ๊ก "ลูกค้า"; ประเภทกิจการใช้ตัวเลือกร่วมกับ "ประเภทกิจการของลูกค้า"; ขั้นตอนของงาน / ลักษณะงาน เป็นตัวเลือกใหม่ที่พิมพ์เพิ่มได้ (seed ตัวอย่างไว้)
- % โอกาสสำเร็จ 10–100 ทีละ 10 (ไม่ระบุได้); มูลค่าทศนิยม 2 ตำแหน่ง; กลุ่ม (tag) ใช้ชุดเดียวกับผู้ติดต่อ
- การรับประกัน: วันเริ่ม, วันสิ้นสุด, หมายเหตุ (ตามที่สเปกให้เริ่มไว้ — ยังรอรายละเอียดจริง)
- ลบ = soft delete (สิทธิ์ลบ) ลบไม่ได้ถ้ามีใบถอดแบบหรือแผนการทำงานที่ยังไม่ยกเลิกอ้างอิง
- "สร้างใบถอดแบบ" → ฟอร์มใบถอดแบบใหม่ที่ดึงลูกค้า + ชื่อโครงการ + ลิงก์โครงการมาให้ (`?project=`); ใบถอดแบบเลือกโครงการ CRM ได้เอง (`engineer_docs.projectId`)
- **"สร้างใบเสนอราคา" เป็นปุ่ม disabled** พร้อมคำอธิบาย (หัวข้อ 10 — รอสเปก)
- หน้าผู้ติดต่อ: คอลัมน์ "จำนวนโครงการ" นับโครงการที่ยังไม่ถูกลบ

### แผนการทำงาน
- สถานะ: วางแผน → (เช็คอิน จุดเริ่มต้น) → เช็คอิน → (เช็คอิน จุดหมาย) → เสร็จสิ้น; "เสร็จสิ้น" / "ยกเลิก" แบบไม่เช็คอินได้จาก วางแผน/เช็คอิน (มี confirm)
- เช็คอินจุดหมายต้องเช็คอินจุดเริ่มต้นก่อน (ไม่มีจุดเริ่มต้นก็คิดระยะทางไม่ได้)
- **เช็คอินได้เฉพาะพนักงานเจ้าของแผน** (แม้ admin) — พิกัดต้องมาจากเครื่องของคนที่ไปหน้างาน;
  เสร็จสิ้นแบบไม่เช็คอิน = เจ้าของหรือสิทธิ์แก้ไข; ยกเลิก = เจ้าของหรือสิทธิ์ยกเลิก; แก้ไขรายละเอียด = เจ้าของหรือสิทธิ์แก้ไข (เฉพาะแผนที่ยังไม่จบ)
- **เวลาเช็คอินใช้เวลาของ server** (ไม่เชื่อนาฬิกาเครื่องผู้ใช้); เก็บ lat/lng (6 ตำแหน่ง) + ความแม่นยำ (เมตร) ที่เบราว์เซอร์รายงาน
- Geolocation: `enableHighAccuracy`, รอไม่เกิน 20 วินาที, ข้อความ error ภาษาไทย —
  **บนมือถือต้องเปิดผ่าน HTTPS** (เบราว์เซอร์ไม่ให้ใช้ตำแหน่งบน http ยกเว้น localhost) ต้องตั้งตอน deploy (เฟส 10)
- ระยะทาง = Haversine (เส้นตรง) เก็บเป็นกม. 3 ตำแหน่ง + `distanceSource`; โครงสร้าง `DistanceProvider` ใน `src/lib/distance.ts`
  เปลี่ยนเป็น Google Distance Matrix ได้โดยเพิ่ม provider (ไม่ต้องแก้ส่วนอื่น) — ยังไม่ทำเพราะต้องใช้ API key/ค่าใช้จ่าย
- ทุกคนที่มีสิทธิ์ดูเมนูเห็นแผนของทุกคน (กรองพนักงาน "ของฉัน"/รายคนได้)
- หน้ารายการ: แท็บ รายการ (ค้นหา/กรองพนักงาน-สถานะ-ช่วงวันที่/Export CSV) + ปฏิทินรายเดือน (กรองพนักงาน/สถานะ, คลิกไปที่แผน)
  ปฏิทินเป็นคอมโพเนนต์ของเราเอง (`src/components/calendar/month-calendar.tsx`) จะเพิ่มมุมมองสัปดาห์/วันในเฟส 9 (ตารางงานพนักงานส่ง)
- หน้ารายละเอียดออกแบบสำหรับมือถือ: ปุ่มเช็คอินใหญ่เต็มความกว้างอยู่บนสุด, ลิงก์เปิดพิกัดใน Google Maps, ระยะทางตัวใหญ่
- แผนการทำงานยังไม่ส่งแจ้งเตือน (สเปกไม่ได้ระบุ)
- รายงาน CRM (ผู้ติดต่อ, โครงการ, บุคคลติดต่อ, ตารางทำงานและระยะทาง, การรับประกัน) ทำในเฟส 9

### แก้ไข: ล็อกอิน/ปุ่มค้างเมื่อเปิดผ่าน IP วงแลน (25/11/2026)
- อาการ: กด "เข้าสู่ระบบ" แล้วค้าง ต้องกด Enter — สาเหตุคือเปิดผ่าน `http://192.168.x.x:3000` แล้ว Next.js 16 dev **บล็อก JS/HMR ของ dev server**
  จาก origin ที่ไม่ใช่ localhost (`allowedDevOrigins`) หน้าเว็บจึงไม่ hydrate ทุกหน้าที่มีปุ่ม/ฟอร์มฝั่ง client ใช้งานไม่ได้
- แก้: `allowedDevOrigins` ใน `next.config.ts` อนุญาต IP วงแลน (192.168/10/172) + เพิ่มเองได้ทาง env `DEV_ALLOWED_ORIGINS`
  (มีผลเฉพาะ `next dev`; production ไม่เกี่ยว) — ตรวจแล้วทุกหน้าในเมนู 37 หน้า ทั้ง localhost และ IP วงแลน ไม่มี error
- หมายเหตุ: เช็คอิน GPS จากมือถือผ่าน `http://192.168.x.x` ยังใช้ไม่ได้ เพราะเบราว์เซอร์ให้ใช้ตำแหน่งเฉพาะ HTTPS/localhost
  ถ้าจะทดสอบบนมือถือตอน dev ใช้ `next dev --experimental-https` หรือ tunnel ที่เป็น https

## เฟส 9: ตารางงานพนักงานส่ง + รายงานทั้งหมด (26/11/2026)

### ตารางงานพนักงานส่ง (`inventory.delivery`)
- "งานจัดส่ง" 1 งาน = 1 เที่ยว ผูกกับใบนำออก **1 ใบนำออกมีได้หลายงาน** (ส่งหลายรอบ) — ใบนำออกที่ยกเลิกแล้วสร้างงานไม่ได้
- ฟิลด์: ใบนำออก, วันเวลาเริ่ม–สิ้นสุดจัดส่ง (มีเวลา เพื่อให้มุมมองสัปดาห์/วันมีความหมาย), พนักงานจัดส่ง (ผู้ใช้ในระบบ), ลิงก์/พิกัด Google Map, ที่อยู่จัดส่ง, หมายเหตุ
  - ที่อยู่จัดส่ง**คัดลอก**จากใบนำออกตอนเลือก (แก้ต่อได้ ไม่เปลี่ยนตามใบนำออกภายหลัง)
  - ช่องแผนที่รับลิงก์ `http(s)://…` หรือพิกัด `lat,lng` (แปลงเป็นลิงก์ Google Maps ให้) — ไม่รับ scheme อื่น (กัน `javascript:`)
- **สถานะ** (สเปกไม่ได้ระบุ เลือกแบบง่ายสุด): `นัดส่ง → ส่งแล้ว` หรือ `ยกเลิก` (มี confirm) ไม่มีการลบ — สิทธิ์ของเมนูนี้จึงเป็น ดู/สร้าง/แก้ไข/ยกเลิก
  - "ส่งแล้ว": พนักงานจัดส่งของงานนั้น (แม้มีแค่สิทธิ์ดู) หรือผู้มีสิทธิ์แก้ไข; "ยกเลิก": สิทธิ์ยกเลิก; แก้ไขรายละเอียด: สิทธิ์แก้ไข เฉพาะงานที่ยังนัดส่ง
  - **ยกเลิกใบนำออก → งานจัดส่งที่ยังนัดส่งถูกยกเลิกตามอัตโนมัติ** (transaction เดียวกัน มีบันทึกในประวัติของงาน)
- สร้างได้ 2 ทาง: ปุ่ม "สร้างงานจัดส่ง" ในการ์ด "งานจัดส่ง" ของหน้าใบนำออก (ล็อกใบนำออก) หรือจากหน้าตารางงาน (เลือกใบนำออกที่ยังไม่ยกเลิก ล่าสุด 300 ใบ)
- หน้า "ตารางงานพนักงานส่ง": แท็บ **ปฏิทิน** (ค่าเริ่มต้น; มุมมอง เดือน/สัปดาห์/วัน, กรองพนักงาน, คลิกงานเพื่อดูรายละเอียด) + แท็บ **รายการ** (ค้นหา/กรองพนักงาน-สถานะ-ช่วงวันที่/Export CSV)
  - งานหลายวันแสดงทุกวันที่ครอบคลุม; กรองช่วงวันที่ = งานที่ช่วงจัดส่ง**ซ้อน**กับช่วงที่เลือก
  - ปฏิทินเป็นคอมโพเนนต์ของเราเอง `src/components/calendar/schedule-calendar.tsx` (ใช้ตารางเดือนร่วมกับแผนการทำงาน) มุมมองสัปดาห์/วันเป็นรายการเรียงตามเวลา (ไม่ใช่ตารางชั่วโมง) เพื่อให้อ่านบนมือถือได้
- ยังไม่ส่งแจ้งเตือนเมื่อมอบหมายงาน/ส่งแล้ว (สเปกไม่ได้ระบุ — เพิ่มได้ภายหลังด้วย outbox เดิม)
- seed กลุ่มสิทธิ์ใหม่ "พนักงานจัดส่ง" (ดูตารางงาน + ดูใบนำออก) และเพิ่มสิทธิ์ตารางงานให้กลุ่ม "คลังสินค้า" (มีผลเฉพาะ DB ใหม่ — DB เดิมให้ admin เพิ่มเองที่ "กำหนดสิทธิ์")

### รายงาน (CRM / คลัง / จัดซื้อ)
- หน้าเดียวต่อโมดูล (`/crm/reports`, `/inventory/reports`, `/purchase/reports`): เลือกรายงานด้านซ้าย → ตัวกรอง → ตารางตัวอย่าง (ไม่เกิน 500 แถว) → **Export CSV ได้ครบทุกแถว**
  - API เดียว `GET /api/reports/[module]/[key]` (`?format=csv`) ตรวจสิทธิ์ "ดู" เมนูรายงานของโมดูลนั้น; นิยามรายงานอยู่ที่ `src/server/reports/*`
  - **สิทธิ์ดูรายงานพอแล้ว** ไม่ต้องมีสิทธิ์ดูเมนูต้นทาง (เช่น รายงานผู้ติดต่อไม่กรองตามสิทธิ์ลูกค้า/ผู้ขาย)
  - CSV: UTF-8 BOM, ตัวเลขเป็นค่าดิบ (ไม่มี comma — Excel คำนวณได้), วันที่ DD/MM/YYYY, มีแถวรวมท้ายไฟล์ (ถ้ารายงานมี)
  - ช่วงวันที่ค่าเริ่มต้น = ต้นเดือนถึงวันนี้; รายงานที่เป็น "ข้อมูลหลัก/ยอดค้าง" (ผู้ติดต่อ, โครงการ, การรับประกัน, SN/Lot, PR/PO ค้าง) ค่าเริ่มต้นไม่กรองวันที่
- **CRM** (5): ผู้ติดต่อ, โครงการ (รวมมูลค่า), บุคคลติดต่อ, ตารางทำงานและระยะทาง (มุมมอง สรุปต่อพนักงาน / รายละเอียดทุกแผน; กรองตามวันเวลาเริ่มของแผน; ระยะทางรวมนับเฉพาะแผนที่มีระยะทาง),
  การรับประกัน (สถานะคิด ณ วันนี้: อยู่ในประกัน / ใกล้หมด ≤ 30 วัน / หมดแล้ว — ใช้ฟิลด์ชั่วคราว วันเริ่ม/วันสิ้นสุด/หมายเหตุ ตามสเปก)
- **คลัง** (5): สินค้าคงคลังตามคลัง/สถานที่ (**ณ วันที่** ย้อนหลังได้ คำนวณจาก movement; มุมมองรวมต่อสินค้า), Stock card (ยอดยกมา + รับ/จ่าย + คงเหลือสะสม + ยอดคงเหลือ ต่อสินค้า),
  รายการนำเข้า (ต่อรายการสินค้า), รายการนำออก (ต่อ SN), รายการ SN/Lot (เฉพาะใบนำเข้าที่นำเข้าแล้ว พร้อมคงเหลือปัจจุบัน)
  - ไม่มีมูลค่าสต๊อก/ต้นทุน — วิธีคิดต้นทุนยังรอสเปก (หัวข้อ 10)
- **จัดซื้อ** (6): รายการ PR (ต่อรายการ + สั่งซื้อแล้ว/คงค้าง), รายการ PO (รวมเป็นเงิน/VAT/ยอดรวมสุทธิ; ยอดรวมไม่นับใบที่ยกเลิก), PR ที่ยังไม่ได้สั่งซื้อ (อนุมัติแล้ว/สั่งซื้อบางส่วน + เกินกำหนดกี่วัน),
  PO ที่ยังไม่ได้รับของ (อนุมัติแล้ว/นำเข้าบางส่วน + มูลค่าคงค้างตามราคารายการ), ใบส่งคืน (+ นำออกแล้ว), ยอดซื้อตามผู้ขาย
  - "สั่งซื้อแล้ว" นับ PO ที่ยังไม่ยกเลิก (รวมร่าง — ตรงกับการกันยอดเกินในเฟส 5); "นำเข้าแล้ว" นับใบนำเข้าที่นำเข้าแล้ว
  - **ยอดซื้อตามผู้ขาย** นับเฉพาะ PO ที่อนุมัติแล้วขึ้นไป (อนุมัติแล้ว/นำเข้าบางส่วน/นำเข้าแล้ว) ตามวันที่ออกเอกสาร + มูลค่าส่งคืน (ตามราคารายการ PO) แยกคอลัมน์ ไม่หักออกจากยอดซื้อ

## เฟส 10: Import ข้อมูลเก่า + เตรียม deploy production (26/11/2026)

### Import ข้อมูลเก่า (ผู้ใช้เลือก: ยังไม่มีไฟล์จากระบบเดิม → ใช้แม่แบบของระบบใหม่)
- สคริปต์ CLI `npm run import -- <ชนิด> <ไฟล์> [--commit]` (ไม่ทำหน้าจออัปโหลด — ใช้ครั้งเดียวตอนย้ายระบบ โดยผู้ดูแล) รายละเอียดที่ `docs/IMPORT.md`
- ชนิด: `contacts`, `contact-persons`, `products`, `projects`, `opening-stock`; แม่แบบ CSV (หัวตารางภาษาไทย + แถวตัวอย่าง) ที่ `data/import-templates/`
- **ค่าเริ่มต้นเป็น dry run**; `--commit` นำเข้าเมื่อทั้งไฟล์ไม่มี error เท่านั้น (มี error = ไม่เขียนอะไร + ไฟล์ `*.errors.csv` บอกแถว/คอลัมน์)
- รันซ้ำได้: รายการที่มีอยู่แล้วถูกข้าม (ผู้ติดต่อ/สินค้าตามรหัส, ผู้ติดต่อไม่มีรหัสตามชื่อ, โครงการตามชื่อ+ลูกค้า, บุคคลติดต่อตามชื่อในผู้ติดต่อเดียวกัน)
- บันทึกผ่าน service เดิม (`createContact`, `createProduct`, `createProject`) จึงผ่าน validation + audit log เหมือนสร้างในหน้าจอ; ผู้ทำ = admin (`--as`)
- ตัวเลือก (lookup), กลุ่ม, หน่วย, หมวดหมู่ (ตาม path `A > B > C`) ที่ยังไม่มี **สร้างให้อัตโนมัติ** (แจ้งในผลตรวจ) — คลัง/สถานที่ และผู้ใช้ **ไม่สร้างให้** (ต้องตั้งในหน้าจอก่อน)
- วันที่รับ `DD/MM/YYYY` / `YYYY-MM-DD` และปี พ.ศ. (ปี > 2400 ลบ 543); ใช่/ไม่ หลายรูปแบบ; ตัวเลขมี comma; CSV ตัวคั่น `,` `;` tab
- **ยอดยกมา**: สร้างใบนำเข้า (อื่นๆ) ที่นำเข้าแล้ว แยกตามคลัง + Lot (ใบละ ≤ 999 SN / 200 รายการ), SN ตาม "จำนวนต่อ SN", movement มีผล ณ `--date` (วันตัดยอด)
  - เพิ่มพารามิเตอร์ `occurredAt` ให้ `postReceipt` (ค่าเริ่มต้นยังเป็นเวลาปัจจุบัน) เพื่อให้รายงาน "คงคลัง ณ วันที่" ถูกต้อง
  - นำเข้าได้เฉพาะสินค้าที่ยังไม่มีความเคลื่อนไหว (กันยอดซ้ำ); แก้ไขด้วยการยกเลิกใบนำเข้าในหน้าจอ
- ยังไม่นำเข้า: เอกสารเก่า (PR/PO/ใบนำเข้า/ออก, ใบถอดแบบ), แผนการทำงาน, ผู้ใช้ — ถ้าต้องการให้ส่งตัวอย่างไฟล์มา

### Deploy (ผู้ใช้เลือก: VPS + Docker)
- `Dockerfile` multi-stage: `runner` (Next.js `output: "standalone"`, user ไม่ใช่ root, HEALTHCHECK) และ `tools` (migrate/seed/import)
- `docker-compose.prod.yml`: `migrate` (รัน `prisma migrate deploy` ทุกครั้งก่อนแอปเริ่ม) → `app` → `caddy` (HTTPS Let's Encrypt อัตโนมัติ, security headers, body 30MB)
- ฐานข้อมูลยังเป็น Supabase (project แยกสำหรับ production); ไฟล์แนบอยู่ใน Docker volume `uploads` (1 instance) — สำรองด้วย `deploy/backup.sh` (pg_dump + tar uploads, cron รายวัน, เก็บ 14 วัน)
- `GET /api/health` ไม่ต้องล็อกอิน ตอบแค่ `{ ok }` (ตรวจต่อ DB ได้) สำหรับ Docker healthcheck / monitoring
- seed: `SEED_SAMPLE_DATA=false` ไม่สร้างข้อมูลตัวอย่าง (ผู้ติดต่อ/คลัง/หมวดหมู่/คุณสมบัติ/สินค้า/ใบนำเข้า-ออกตัวอย่าง) — ยังสร้าง admin, กลุ่มสิทธิ์, ตัวเลือกพื้นฐาน, หน่วย, เหตุผลส่งคืน, หมายเหตุสำเร็จรูป
- ตรวจแล้ว: `npm run build` ผ่าน และรัน e2e 18 เทส (foundation, จัดซื้อ, ถอดแบบ, งานจัดส่ง/รายงาน) กับ standalone build ผ่านทั้งหมด
  — **ยังไม่ได้ทดสอบ build Docker image จริง** (เครื่อง dev ไม่มี Docker) ต้องตรวจครั้งแรกบน VPS
