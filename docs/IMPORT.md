# นำเข้าข้อมูลเก่า (CSV)

สคริปต์นำเข้า ผู้ติดต่อ, บุคคลติดต่อ, สินค้า, โครงการ และยอดคงคลังตั้งต้น จากไฟล์ CSV ตาม**แม่แบบของระบบใหม่**
(ระบบเดิมไม่มีไฟล์ Export ให้ดูรูปแบบ — เมื่อได้ไฟล์จากระบบเดิม ให้จัดคอลัมน์ให้ตรงแม่แบบใน Excel ก่อน)

## ขั้นตอน

1. **สร้างแม่แบบ** (มีอยู่แล้วที่ `data/import-templates/`)
   ```bash
   npm run import -- templates
   ```
2. เปิดแม่แบบใน Excel → ลบแถวตัวอย่าง → วางข้อมูลจริง → **Save As "CSV UTF-8 (Comma delimited)"**
   เก็บไฟล์จริงไว้ที่ `data/` (โฟลเดอร์นี้ไม่ถูก commit ยกเว้นแม่แบบ)
3. **ตรวจก่อน** (ไม่เขียนฐานข้อมูล):
   ```bash
   npm run import -- contacts data/contacts.csv
   ```
   ถ้ามีข้อผิดพลาด จะได้ไฟล์ `data/contacts.errors.csv` บอก แถว / คอลัมน์ / ปัญหา → แก้แล้วรันใหม่
4. **นำเข้าจริง** เมื่อไม่มี error:
   ```bash
   npm run import -- contacts data/contacts.csv --commit
   ```
5. ทำตามลำดับ (ข้อมูลหลังอ้างอิงข้อมูลก่อนหน้า):

| ลำดับ | ชนิด | ไฟล์แม่แบบ | อ้างอิง |
|---|---|---|---|
| 1 | `contacts` | ผู้ติดต่อ (ลูกค้า/ผู้ขาย) + บุคคลติดต่อหลัก 1 คน | — |
| 2 | `contact-persons` | บุคคลติดต่อเพิ่มเติม | รหัสผู้ติดต่อ |
| 3 | `products` | สินค้า (+ คอลัมน์คุณสมบัติ) | — |
| 4 | `projects` | โครงการ CRM | รหัสลูกค้า, อีเมลพนักงานขาย |
| 5 | `opening-stock` | ยอดคงคลังตั้งต้น | รหัสสินค้า, รหัสคลัง, รหัสสถานที่ |

ก่อนทำข้อ 4–5 ต้องมี: ผู้ใช้ (พนักงานขาย) และ **คลัง/สถานที่จัดเก็บ** ใน "ตั้งค่า > ตั้งค่าคลัง" (สร้างผ่านหน้าจอ)

## กฎสำคัญ

- **มี error แม้แถวเดียว = ไม่นำเข้าเลย** (แก้ไฟล์แล้วรันใหม่ทั้งไฟล์)
- **รันซ้ำได้**: แถวที่มีอยู่แล้วจะ "ข้าม" ไม่สร้างซ้ำ
  - ผู้ติดต่อ: รหัสซ้ำ → ข้าม (ไม่ใส่รหัส: ชื่อซ้ำกับที่มีอยู่ → ข้าม); ไม่ใส่รหัส = ออกรหัส CT00001… อัตโนมัติ
  - บุคคลติดต่อ: ชื่อซ้ำในผู้ติดต่อเดียวกัน → ข้าม
  - สินค้า: รหัสซ้ำ → ข้าม
  - โครงการ: ชื่อซ้ำกับโครงการของลูกค้าเดียวกัน → ข้าม
  - **ยอดยกมา: นำเข้าได้เฉพาะสินค้าที่ยังไม่มีความเคลื่อนไหวในคลัง** (กันนับยอดซ้ำ) — ถ้าต้องแก้ ให้ยกเลิกใบนำเข้าที่สร้างไปแล้วในหน้าจอ
- ตัวเลือกที่ยังไม่มี (ช่องทางที่รู้จัก, ประเภทกิจการ, ประเภทสินค้า, ขั้นตอน/ลักษณะงาน), กลุ่ม (tag), หน่วย, หมวดหมู่ → **สร้างใหม่ให้อัตโนมัติ** (รายงานไว้ตอนตรวจ)
- ทุกรายการที่นำเข้ามีประวัติ (audit log) ผู้ทำ = admin (`--as อีเมล` เปลี่ยนได้ ต้องเป็น admin)

## รูปแบบค่า

| ชนิด | รูปแบบที่รับ |
|---|---|
| วันที่ | `DD/MM/YYYY`, `D/M/YYYY`, `YYYY-MM-DD` — ปี > 2400 ถือเป็น พ.ศ. (เช่น `31/12/2569` = 31/12/2026) |
| ใช่/ไม่ | `ใช่` `ไม่` `Y` `N` `1` `0` `x` (ว่าง = ค่าเริ่มต้นของคอลัมน์) |
| ตัวเลข | มี comma ได้ เช่น `192,085.50` |
| หลายค่า | คั่นด้วย `,` หรือ `;` เช่น โทรศัพท์ `02-111-1111, 081-222-2222`, กลุ่ม `VIP, กรุงเทพ` |
| หมวดหมู่สินค้า | `ระดับ1 > ระดับ2 > ระดับ3` |
| สถานที่จัดเก็บ | รหัสสถานที่ (ถ้าไม่ซ้ำในคลัง) หรือเส้นทางรหัส `A > A-1 > A-1-01`; ว่าง = ระดับคลัง |
| สถานะโครงการ | ชื่อภาษาไทยตาม stepper เช่น `เสนอราคา`, `ปิดได้` (ว่าง = โครงการใหม่) |

ไฟล์รับได้ทั้งตัวคั่น `,` `;` และ tab, มี/ไม่มี BOM

## ยอดคงคลังตั้งต้น

```bash
npm run import -- opening-stock data/opening-stock.csv --date 31/12/2026 --commit
```
- สร้าง **ใบนำเข้า (ประเภทอื่นๆ) สถานะนำเข้าแล้ว** แยกตาม คลัง + Lot (ใบละไม่เกิน 999 SN / 200 รายการ) หมายเหตุ "ยอดยกมา — นำเข้าจากไฟล์ …"
- `จำนวนต่อ SN` แบ่งเป็นหลาย Barcode/SN เช่น 120 ÷ 10 = 12 SN (เศษอยู่ SN สุดท้าย) — ว่าง = 1 SN ต่อแถว
- `--date` = วันตัดยอด: วันที่เอกสารและวันที่มีผลของยอด (รายงาน "คงคลัง ณ วันที่" / stock card เห็นยอดตั้งแต่วันนั้น)
- พิมพ์ label Barcode ได้จากหน้าใบนำเข้าแต่ละใบ แล้วนำไปติดสินค้าจริง
